点「导入」会把预设展开成普通规则追加进规则表，之后可以随意改、随意删。重复的规则不会重复导入。

播放页

这里有两件事不在「过滤规则」表里。一是你此刻正在看的这位 UP：他的其它稿件一律放行，哪怕命中了任何规则—— 这是身份级豁免，不是一条规则。二是右侧偶尔插在第一个位置的运营推广卡（指向 /toy/、/blackboard/ 这类站内活动页）和右侧底部的广告横幅： 它们没有 bvid，也没有播放量、时长、UP 这些字段，规则引擎判定不了，只能按推广信号整卡隐藏。

默认开。右侧推荐里出现正在看的这位 UP 的其它稿件时直接放行：哪怕命中了「已屏蔽的 UP」、标题关键词、播放量、时长、互动率或 UP 投稿频率里的任何一条， 也不拦它，更不会为它发远程请求。只按 UP 身份（mid）识别；首页不适用，拿不到当前 UP 是谁时照常过滤。

默认开。判据：链接指向活动页、带 specialRecommend 运营推荐位、带 cm.bilibili.com 推广打点， 或者容器带 ad-report / ad-floor / advert 广告位标记。指向普通视频、番剧、直播、课程、漫画的卡片一律不碰， 避免把用户想看的番剧或直播当成广告藏掉。关掉开关后刷新页面即可恢复。

主站

除了视频播放页，也可以管一管 www.bilibili.com 首页的推荐流。首页的普通视频卡片同样走上面的规则表； 番剧、影视、课程、直播、广告这些卡片没有 bvid，也拿不到时长/播放量，走不了规则引擎，只能在下面按类别整类隐藏。

默认开。关掉后首页完全不管，规则表仍然作用在播放页。

默认关。标签关键词和 UP 主投稿频率要逐条请求 B 站接口，而首页会无限滚动、卡片数量没有上限。 开启后也只对滚到视口附近的卡片发请求，并受「高级 → 每页最多额外请求数」限制。

这些卡片没有 bvid 和元数据，不参与规则判定，也不能按播放量/时长过滤。

高级

这些开关影响性能与风控风险，不确定就保持默认。

关闭后「标签关键词」和「UP主投稿频率」规则完全不生效，只用接口自带字段判定，零额外请求。

一个播放页右侧约 40 条推荐，标签需要逐条请求，UP 频率按 UP 去重。调低可以显著降低风控风险，代价是部分卡片判定为「未知」而放行。

播放量低于此值时，点赞率/投币率等视为不可信，不参与判定。

鼠标移到卡片上出现「屏蔽此UP」「标题词+」。

导出会把规则、批量关键词、白名单、黑名单和高级设置一起存成一个 JSON 文件，方便备份或换电脑时迁移。 导入会覆盖当前全部配置，导入前会再确认一次。

WebDAV 同步

把「过滤规则、批量关键词、白名单 / 黑名单」同步到自己的 WebDAV（坚果云、Nextcloud 等）。 播放页 / 主站的显示偏好、远程开关、命中日志都留在本机，不同步。 多台机器的改动会自动合并：两边各自加的规则和关键词都会保留，删掉的也会同步删除（删除记录保留 30 天）。 同类型的关键词规则（例如两条「标题关键词」）会合并成一条，词表取并集。

开启后，每次规则变更都会自动上传合并一次；浏览器启动和每次打开这个设置页时也会拉取一次云端改动。

填到 WebDAV 根目录为止，带不带结尾斜杠都行。

坚果云要用「应用密码」（账户信息 → 安全选项 → 添加应用密码），登录密码在 WebDAV 上不可用。 凭据只存在本机 chrome.storage.local，不进同步文件，也不会被打进「导出配置」。

会在服务器根目录下建这个文件夹，里面是 settings.json 和最多 10 份历史备份。

「保存并测试」会顺带申请访问该服务器的权限（浏览器会弹一次确认）。 「重置同步基线」只清掉本机的合并基线，下一次同步会把云端和本机重新并一次，不会删数据。
